# AjaxBridge 2.1.2

Released November 11, 2026. This maintenance release collects the dependency and container updates since 2.1.1. It does not change device mappings, MQTT topics, Home Assistant unique IDs, source isolation, physical controls, or stored state formats. No migration is required from 2.1.1.

## Bridge and container maintenance

The bridge uses Go 1.27.4, including the `net/http` fix for [GO-2026-6859 / CVE-2026-97054](https://pkg.go.dev/vuln/GO-2026-6859), plus Chi 5.5.0, Prometheus common 0.73.1, and procfs 0.23.0. `golang.org/x/net` is updated to 0.62.0, including the HTML advisory fixes, together with compatible Go tooling and transitive dependencies. The Go builder is digest-pinned and the runtime uses Alpine 3.24.3.

Both `rcooler/ajax-bridge:2.1.2` and the compatibility image `rcooler/ajax2prometheus:2.1.2` support linux/amd64 and linux/arm64. Release automation continues to produce checksums, SBOMs, signatures, and attestations. GoReleaser, Syft, Cosign, Trivy, and the relevant GitHub Actions pins are refreshed.

## Home Assistant cards

The card package is version 2.1.2 and uses Node.js 24.22.2 LTS, npm 12.2.2, React/ReactDOM 19.3.1, Vite 8.3.6, React plugin 6.2.1, Rolldown 1.3.0, and TypeScript 7.0.2. Updated linting tools have two narrow exceptions for existing effect-local variables; camera and dashboard behavior is unchanged.

Install the complete `ha-cards-dist.tar.gz` bundle, including its chunks, images, CSS, and hidden Vite metadata. Stage it in an immutable content-hashed directory and verify the files served by HA before replacing the existing AjaxBridge module resource URL. Do not register a second copy of the card. Refresh open dashboards after activation; a card-only update does not require an HA restart.

## Optional Jeedom components

The refreshed `jeedom/jeedom:4.6-bookworm` base contains Jeedom 4.6.2 and PHP 8.2.35. Rebuilding the custom runtime updates its image dependencies but does not replace an existing mounted HTML installation or bootstrap an existing database. Keep each site's HTML, database configuration, MQTT root, and bridge source ID unchanged.

`AjaxBridge_2.1.2_jeedom_patch.zip` packages the unchanged plugin bundle **2026.10.09.1**. There are no new plugin telemetry mappings or command-ID migrations in this release. An installation already using that bundle does not need it reapplied solely for 2.1.2. The external-database runtime remains source-only under `deploy/jeedom-external`; no separate Jeedom image is published.

## Upgrade and rollback

1. Retain the previous bridge image digest, card resource URL, and backups of runtime data and private configuration. Keep Jeedom HTML/database backups when rebuilding its optional runtime.
2. Pull and recreate the bridge using `rcooler/ajax-bridge:2.1.2` or `rcooler/ajax2prometheus:2.1.2`. Source-build installations must rebuild from this release with `VERSION=2.1.2`, the release commit, and build date. Preserve all existing data mounts.
3. If using the custom Jeedom runtime, copy its release build context and rebuild/recreate those containers separately. Do not run `seed`, `bootstrap`, or migration commands against populated installations as an upgrade step.
4. Stage and verify the complete card bundle using the [card release helper](../../../ha-cards/README.md), replace the one existing resource URL, and refresh open dashboards. Keep the prior release folder for rollback.
5. After the operator restarts the containers, confirm readiness, expected device/command ownership, MQTT availability, and Prometheus source labels. Do not delete/recreate HA entities or exercise physical controls as part of verification.

For rollback, restore the previous image or rebuild its exact source commit, and switch the card resource back to its previous URL. Restore matching Jeedom backups only if its HTML or database was separately changed. Publishing the release or copying build inputs does not restart running containers.

Upgrades from before 2.1.1 must also follow the [2.1.1 migration guidance](./2.1.1.md); installations on 2.0.1 or earlier need the [electrical unit and history guidance](./2.1.0.md).
