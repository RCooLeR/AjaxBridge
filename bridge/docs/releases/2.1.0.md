# AjaxBridge 2.1.0

This release covers the bridge, Home Assistant cards, and optional Jeedom telemetry patch changes since 2.0.1. It adds device and diagnostic coverage while correcting ownership, unknown-state handling, and electrical units. Existing command MQTT unique IDs remain stable; historical numeric values are not automatically converted or deleted.

## Jeedom and Prometheus

Each Prometheus scrape reads a consistent Jeedom store snapshot. Restored cache and discovery observations are exported immediately, including temperature and battery values, without waiting for the next MQTT event. Removed commands, previous owners, and obsolete mappings stop producing series on the next scrape.

Numeric values are accompanied by boolean diagnostics, a bounded set of enum states, reported timestamps, receipt timestamps, and observation-age metrics. Missing and non-finite values are omitted; a measured zero remains zero. `keep_last` preserves the observation's original timestamp. Metadata refreshes and process restarts do not reset value age. Old cache entries without a known observation timestamp can expose a value without claiming an age. `/metrics` supports OpenMetrics negotiation and unit metadata while retaining Prometheus text support. See the [metric reference](../prometheus.md).

The exporter includes button/device operating modes, Jeweller/Wings antenna status, battery-check outcomes and a firmware info metric for validated dotted numeric versions. Template-based tests exercise the packaged Jeedom telemetry through discovery and metric collection. Free-form event text and unsupported firmware formats remain available in the JSON/MQTT model rather than becoming arbitrary Prometheus labels.

The Jeedom model also gains:

- Broader Button, SpaceControl, WaterStop, ReX, MultiTransmitter, LifeQuality, and FireProtect diagnostics, including separate smoke, heat and CO states.
- Stable logical/generic metadata and command-ID matching ahead of translated display-name fallbacks; ambiguous aliases no longer silently bind unrelated devices.
- Unique ownership of physical command IDs, reconciliation of removed commands, and persisted retries for obsolete Home Assistant discovery cleanup. Command listings retain per-device synthetic observations.
- Canonical Relay voltage preservation across cache reloads and metadata reconciliation.
- An admin matching view with linked/unlinked summaries, canonical command details, numeric-ID merging, and notification metrics from the live model.

## Electrical units and existing history

Source unit metadata now establishes electrical quantity and scale. The bridge records that provenance, preserves explicit units, and uses declared prefixes for typed metrics. For example, a verified `1000 mA` observation remains `1000` in the generic command series and becomes `1` in the amperes device series. It does not infer a divisor from the value's magnitude or a command name.

| Source contract | Result |
| --- | --- |
| Explicit `A`, `mA`, or microampere unit | Current sensor and a correctly normalized typed amperes metric. |
| Explicit `W`, `kW`, or `mW` | Power sensor and a correctly normalized typed watts metric. |
| Explicit energy unit such as `Wh` or `kWh`, including legacy `powerWtH` commands | Energy sensor with `total_increasing`; generic command values retain the declared unit. |
| Missing or unverified current/power unit | Raw numeric diagnostic; no invented physical device class or typed amperes/watts series. |
| Energy name without a verified supported source unit | `energy_raw`, including after cache reload; no inferred kWh or physical counter metadata. |

Legacy caches cannot always distinguish an actual source A/W unit from an older bridge default. Ambiguous current/power entries are conservatively restored as raw, preserving their numbers. An explicit blank-unit event invalidates the previous unit contract; a value-only event that omits unit metadata retains a verified contract. Changing a unit contract requires a fresh matching observation before reusing its number. Known electrical entities retain discovery and identity when their value is unknown; unknown is not published as zero.

Before changing an existing Jeedom command, inspect both its unit and `calculValueOffset`. Some commands already convert mA to A or Wh to kWh in Jeedom. Applying a second conversion would corrupt the reading. MQTT discovery does not expose the full formula contract; use the Jeedom UI or the [read-only electrical audit helper](../../../Jeedom/tools/README.md). The supplied WallSwitch template declares mA/Wh without adding a conversion formula, but it deliberately leaves existing command settings unchanged.

Home Assistant entity identity and statistics metadata are separate. Correcting the current entity does not fix earlier samples recorded under an incorrect unit or quantity. In particular, an old cumulative energy reading labelled W is not an instantaneous power measurement. Back up statistics and inspect the actual historic source contract before changing metadata or scale. Where old graphs must remain available as a record of earlier readings, keep a separate archive with verified units and verify its complete numeric readback before updating the active series. Do not delete and recreate entities merely to silence a statistics warning. No general-purpose historical repair is applied by this release.

Prometheus and Home Assistant Recorder store history independently. Recorder exclusions can remain in place while Prometheus scrapes the bridge; Prometheus retention is configured on the Prometheus server. Neither the bridge cache nor a Recorder metadata correction backfills missing history. Corrections may change the metric label from `power_raw` to `energy_wh`, for example; earlier samples keep their original labels and values. Review dashboards and alerts at that boundary instead of treating the old samples as corrected data.

## Observed state and Home Assistant cards

Device observations take precedence over configuration and requested actions. Cache restoration preserves trustworthy state and successful control state; an ambiguous legacy state inferred only from newly demoted electrical data becomes unknown. Positive verified load can establish that an action-only WallSwitch is on, but zero load does not prove that it is off. Raw readings and cumulative energy do not establish relay state.

The cards resolve Ajax entities through stable ownership and metadata, including legacy suffixed entity names. They retain the full power-device inventory, show operational diagnostics separately from security alarms, and display physical Button/SpaceControl devices as read-only. Unknown or intermediate state disables dependent controls at both rendering and dispatch. Security actions require confirmation, and failed service requests are not automatically retried.

Electrical cards use verified units. Voltage times current is labelled **apparent power (VA)**; it is not presented as measured active power. Energy remains energy even when the entity has a historic Power name. Raw readings do not produce a derived VA value.

The card release helper stages the complete build in an immutable directory, records file hashes, and verifies every served asset before an operator switches the Home Assistant resource URL. Keep the previous release directory and URL for rollback. See the [card installation guide](../../../ha-cards/README.md).

## Included Jeedom patch

The dedicated release asset `AjaxBridge_2.1.0_jeedom_patch.zip` contains `Jeedom/` at its root, including bundle **2026.09.25.1**, source overlays, provenance, licenses, checksums, verification, and offline validation. Extract the archive and follow [Jeedom/README.md](../../../Jeedom/README.md). The same directory is included in the repository source archive.

Install the official Ajax Systems plugin from Jeedom Market first. The patch updates that existing installation; it is not a complete replacement plugin and is not installed by the bridge Docker image. Its files retain upstream GPL/AGPL terms rather than the bridge's MIT license. Check the installed baseline and back up Jeedom before copying the overlay or synchronizing commands.

The bundle adds missing telemetry commands and templates without adding per-metric polling. It adds explicit mA/Wh defaults for new WallSwitch commands, preserves existing command IDs/settings/history, and supports checksum verification of an upgrade from bundle 2026.09.24.1. Cloud data availability still determines which readings arrive. See [Jeedom metrics](../../../Jeedom/METRICS.md) and [licensing](../../../Jeedom/LICENSING.md).

## Upgrade from 2.0.1

1. Save the current image digest, Compose configuration, bridge data directory, Home Assistant card resource URL, and any electrical statistics needed for rollback. Back up Jeedom separately if applying its optional patch.
2. Audit electrical command units and formulas before editing them. Preserve already-correct conversions and keep uncertain values raw until their source contract is established.
3. In the existing Compose project, select `rcooler/ajax-bridge:2.1.0` after publication, pull it, and recreate only the bridge service. Keep the existing data mount and private environment settings; the non-root container must be able to write its `/data` files.
4. Check readiness, `/admin`, and `/metrics`. Compare command ownership and values after startup, confirm observation ages are retained, and check that unknown values do not appear as zero. SIA remains the authoritative security input.
5. If using the Jeedom patch, follow its baseline verification, backup, installation, synchronization, and rollback procedure. Confirm that existing commands still have the intended unit/formula before forwarding fresh values.
6. Stage and verify the complete Home Assistant card build, then replace the existing AjaxBridge resource URL. Avoid loading two versions of the module simultaneously. Check observed state, read-only devices, and unknown controls.
7. Review Home Assistant statistics warnings and Prometheus queries for any quantity/label changes. Preserve Recorder exclusions unless you deliberately choose a separate recording-policy change. Historical repair is an installation-specific operation, not an automatic upgrade step.

For rollback, restore the previous image and card resource URL together with the matching saved bridge configuration/cache if needed. A backend rollback does not undo Jeedom command changes or Home Assistant statistics edits; use their separate backups and recorded migration steps. Retain the upgrade backup until the new data and history boundaries have been verified.
