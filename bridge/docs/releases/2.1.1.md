# AjaxBridge 2.1.1

Released October 12, 2026. This patch release covers the bridge, Home Assistant cards, and optional Jeedom tooling since 2.1.0. It includes PR #10 and the verified fixes for MQTT recovery, multiple installations, and Jeedom running against MySQL 8.4. Upgrading does not require renumbering devices or recreating Home Assistant entities.

## Dependency fixes

Go 1.27.2 and `golang.org/x/net` 0.60.0 replace the vulnerable versions reported by the dependency checks. Vite is updated to 8.3.3. The cards retain Node.js 24.21.0, npm 12.2.0, React 19.3 and TypeScript 7.0.2, with current compatible plugin and lint dependencies. Container builds update packages on the pinned Alpine 3.24.2 base.

## MQTT recovery and state ordering

The bridge now listens for Home Assistant's MQTT startup message and resends discovery, availability, and the latest cached SIA/Jeedom state even when values are unchanged. Replies are delayed by 2–5 seconds and repeated startup messages are coalesced. Per-entity ordering prevents a slow replay from overwriting newer SIA state. Actuator commands are never replayed, and cached observations do not become fresh measurements.

The default startup topic is `homeassistant/status` with payload `online`. Custom HA configurations can use `AJAXBRIDGE_MQTT_HA_STATUS_TOPIC` and `AJAXBRIDGE_MQTT_HA_ONLINE_PAYLOAD`; an explicitly empty topic disables this recovery path. Both bridges serving one HA use that HA's topic, while their outgoing identities remain separate. See [MQTT recovery](../home-assistant.md#recovery-after-home-assistant-restarts).

## Separate installations

An optional `AJAXBRIDGE_SOURCE_ID` separates MQTT topics, Home Assistant identities, data paths and Prometheus labels. Cards can filter by source, and each Jeedom installation must use its own MQTT Manager root. Ajax zone numbers and Jeedom command IDs do not need offsets.

Keep the source ID empty for an existing unprefixed installation. Keep any already-configured prefix unchanged: changing it creates a new identity namespace rather than migrating history. Use the [multiple-installation guide](../multiple-installations.md) when adding another site.

## Jeedom fixes and packaging

The optional [external-database runtime](../../../deploy/jeedom-external/README.md) uses bind-mounted HTML and an existing MySQL 8.4 server. Installation and migration are explicit operations. Its startup patcher validates supported core source before applying narrow MySQL compatibility changes, saves originals outside the webroot, and preserves ownership and permissions. The listener-maintenance fix quotes reserved SQL identifiers without changing event dispatch. Service PID permissions no longer make a running MQTT daemon appear stopped.

`AjaxBridge_2.1.1_jeedom_patch.zip` contains plugin bundle **2026.10.09.1**, including the guarded installer, Hub 2 Plus channel diagnostics, and defensive handling of invalid Socket telemetry. Install the official Ajax Systems plugin first and follow the included [plugin instructions](../../../Jeedom/README.md). Existing command IDs, formulas, units and history are not automatically replaced.

The plugin ZIP and external-database runtime are separate. The runtime Dockerfile and scripts are in the source archive under `deploy/jeedom-external`; this release does not publish a separate Jeedom image. Rebuild and recreate custom Jeedom containers to receive its SQL and PID fixes.

## Home Assistant cards

Grid inputs are explicitly mapped in card configuration, using entity IDs or stable registry unique IDs. Mapped utility outages are informational and excluded from the alarm count. Chips without backing sources are hidden, while valid zero readings remain visible. Chip details explain totals and list the relevant devices. Hub connectivity distinguishes enabled interfaces from active uplinks, and analytics categories are separated from scrollable room groups.

## Upgrade and verification

1. Back up bridge data, Compose/environment configuration, the current card resource URL, and Jeedom HTML/database data if using the optional runtime or plugin patch. Keep existing source IDs and Jeedom MQTT roots unchanged.
2. Pull and recreate the bridge with `rcooler/ajax-bridge:2.1.1` or compatibility image `rcooler/ajax2prometheus:2.1.1`. Source-build installations must rebuild before recreating. Keep their existing data mounts.
3. If using the custom external-database runtime, update its build context from this release and rebuild/recreate those Jeedom containers separately. Do not bootstrap an existing schema or replace populated HTML with a fresh installation.
4. Verify bridge readiness, device/command ownership in `/admin`, MQTT availability, and Prometheus source labels. Confirm fresh Jeedom values arrive and that an HA MQTT restart restores discovery without issuing physical commands. Do not delete/recreate unavailable entities as an upgrade step.
5. Stage the complete card archive, verify served assets using the [card release helper](../../../ha-cards/README.md), and replace the existing resource URL. Avoid loading two card versions together. Review source filters and configured grid inputs.

No release step automatically changes Home Assistant Recorder, converts old statistics, renumbers devices, or operates relays and valves. For upgrades from 2.0.1 or earlier, also follow the [2.1.0 electrical-unit guidance](./2.1.0.md).

For rollback, retain the previous image digest and card resource URL. Restore their matching bridge configuration/cache if necessary; restore Jeedom core/plugin files and database from their separate backups when rolling back those changes. Publishing a release does not install it or restart running containers.
