# Патч Ajax Systems для Jeedom

Комплект **2026.10.09.1**, підготовлений 9 жовтня 2026 року. Він додає телеметрію й шаблони пристроїв до плагіна Jeedom `ajaxSystem`, активні uplink-канали та Jeweller-діагностику Hub 2 Plus, стан увімкнення для WallSwitch/Relay і явні одиниці mA/Wh для нових команд WallSwitch. Детальний перелік: [METRICS.md](./METRICS.md). Також усунуто збій Socket на некоректному кеші без зміни формул і шаблонів.

**Перед застосуванням придбайте та встановіть офіційний плагін Ajax Systems через [Jeedom Market](https://market.jeedom.com/index.php?certification=Officiel&p=market&type=plugin&v=d) у своєму обліковому записі.** Ця папка містить лише файли для оновлення наявного плагіна. Вона не надає доступу до хмари, облікового запису, офіційної підтримки чи оновлень Jeedom.

Архів релізу містить усю папку `Jeedom/`, включно з прихованим `.gitattributes`. `SHA256SUMS` охоплює кожен файл комплекту, крім самого списку сум; `manifest.json` описує лише 44 робочі файли накладки. Каталоги `tools/` і `validation/` не копіюються до плагіна.

Копіюйте **вміст `files/`** у корінь встановленого `ajaxSystem`, з об'єднанням папок і заміною однойменних файлів. Не замінюйте папку плагіна лише цим комплектом: решта офіційного плагіна потрібна для роботи. Зображення, облікові дані, база Jeedom та файли самого AjaxBridge сюди не входять. `Relay.json` і шаблони Socket не замінюються.

Для нової квартири використовуйте [окрему чисту інсталяцію та інструкцію SIA](APARTMENT_SETUP.md). [Офлайн-інсталятор](tools/install-patch.sh) спочатку перевіряє сумісність у режимі `--check`, а `--apply` створює копію оригінального плагіна й переносить тільки накладку. Перед застосуванням вимкніть Ajax Systems; не переносіть базу, токени чи кеш будинку.

У WallSwitch нові `currentMA` та `powerWtH` мають одиниці **mA** та **Wh**, без формули перерахунку; назва лічильника — «Consommation». Синхронізація додає лише відсутні команди: одиниці, формули, ID та історія наявних команд залишаються. Для старих команд виправлення одиниць виконується окремо після перевірки фактичних значень і формул; цей комплект автоматично їх не мігрує.

Для Hub 2 Plus команди `activeChannel::ETHERNET`, `activeChannel::WIFI` і `activeChannel::GSM` обчислюються лише з послідовного списку відомих рядкових enum у полі API `activeChannels`. Некоректний масив не очищає останні показання; порожній коректний список очищає. Окремі `ethernet::enabled`, `wifi::enabled` та `gsm::gprsEnabled` є налаштуваннями інтерфейсів, а не доказом активного uplink. Для Jeweller доступні шум і параметри опитування; API не надає єдиного стану «Jeweller connected», тому пакет його не вигадує.

## Як збираються дані та чи додаються запити

Шлях даних: **Ajax → хмара Jeedom → плагін Ajax Systems → MQTT Manager → AjaxBridge → Home Assistant / Prometheus / HTTP**. SIA залишається окремим основним джерелом охоронних подій AjaxBridge.

Під час штатної синхронізації плагін отримує хаби, списки пристроїв, їхні деталі й групи. Поточні callback передають події та оновлення полів. Патч додає команди та розбирає поля в цих уже отриманих повідомленнях. Нових endpoint, періодичного опитування або окремого запиту на кожну метрику немає. **Сама синхронізація робить свої звичайні мережеві запити**; твердження про відсутність додаткових запитів стосується нових метрик, а не всієї роботи плагіна. Нові значення можуть створювати додаткові локальні події MQTT/записи історії.

Дані з'являються лише тоді, коли відповідні поля надійшли від пристрою через хмару. Відсутнє або `null` поле зберігає попереднє значення; воно може бути застарілим. Патч не гарантує частоти оновлень і не додає автоматизації коротких/довгих натискань Button.

## Встановлення через SSH

Приклад для типової Linux-інсталяції в `/var/www/html`. Замініть шляхи відповідно до вашої системи. Для Docker виконуйте команди у файловій системі/томі Jeedom; зміни лише всередині тимчасового контейнера зникнуть після його перестворення.

### 1. Передайте й перевірте комплект

Скопіюйте **всю папку `Jeedom`** на сервер, наприклад у `/tmp/ajaxbridge-jeedom`. Не переносіть лише `files/`: для перевірки потрібні інші файли комплекту. Команди нижче виконуйте в одній Bash-сесії:

```bash
set -euo pipefail
PACKAGE=/tmp/ajaxbridge-jeedom
PLUGIN_DIR=/var/www/html/plugins/ajaxSystem

test -f "$PACKAGE/manifest.json"
test -f "$PLUGIN_DIR/plugin_info/info.json"
php "$PACKAGE/verify.php"
php "$PACKAGE/verify.php" --base "$PLUGIN_DIR"
```

Перша перевірка має вивести `Bundle checksums OK`. Друга порівнює 44 робочі файли з відомими базовими/патченими варіантами; нові шаблони можуть бути відсутні. Вона не завантажує Jeedom і не надсилає запитів.

Оновлення з комплекту **2026.09.24.1** також проходить `--base`: його попередній `WallSwitch.json` приймається лише за точним SHA-256 `0757854ceea3343fa6b8e5c6dfad661164a830cc3be4004c38ae1df70f4a792c`, записаним у `previous_packaged_sha256`. Довільні правки цього шаблону залишаються `REVIEW`; перевірка `--installed` вимагає вже поточні файли комплекту.

Окремо приймаються точні LF-нормалізовані суми офіційних stock-шаблонів SpaceControl і Transmitter, датованих 16.04.2026 та перевірених 09.10.2026. Їх записано в `reviewed_upstream_sha256_lf`, не як попередні версії комплекту: відмінності лише в доданих battery/issues/firmware командах SpaceControl і температурі Transmitter. Будь-яка інша правка залишається `REVIEW`; `--installed` не приймає stock замість поточного патча.

Якщо бачите `REVIEW`, **не продовжуйте сліпу заміну**. Перевірте вказані файли, наприклад `diff -u "$PLUGIN_DIR/core/class/ajaxSystem.class.php" "$PACKAGE/files/core/class/ajaxSystem.class.php"`, і перенесіть потрібні правки з урахуванням установленої версії. Відмінність `Transmitter.json` можлива через згадану попередню локальну зміну. Після ручного злиття точні контрольні суми вже відрізнятимуться: збережіть власний diff і перевірте результат окремо. Комплект орієнтований на відому базу; невідомий результат перевірки не є підтвердженням сумісності.

### 2. Зробіть копію файлів і застосуйте заміну

Після повної резервної копії Jeedom оберіть коротке вікно обслуговування й **вимкніть плагін у Jeedom**, щоб не виконувати callback у момент заміни кількох пов'язаних файлів. Налаштування з'єднання не видаляйте. Поки плагін вимкнений, його події можуть бути пропущені.

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
BACKUP_DIR=/var/backups/ajaxbridge-jeedom/$STAMP
sudo install -d -m 700 "$BACKUP_DIR"
sudo cp -a "$PLUGIN_DIR" "$BACKUP_DIR/ajaxSystem"
printf 'File backup: %s\n' "$BACKUP_DIR/ajaxSystem"

# Об'єднання вмісту files/ з наявним плагіном; решта файлів залишається.
sudo cp -R "$PACKAGE/files/." "$PLUGIN_DIR/"

# Власник — як в оригінальних метаданих плагіна, права — без запису для всіх.
while IFS= read -r -d '' entry; do
  relative=${entry#"$PACKAGE/files/"}
  sudo chown --reference="$PLUGIN_DIR/plugin_info/info.json" "$PLUGIN_DIR/$relative"
  if [ -d "$entry" ]; then
    sudo chmod 755 "$PLUGIN_DIR/$relative"
  else
    sudo chmod 644 "$PLUGIN_DIR/$relative"
  fi
done < <(find "$PACKAGE/files" -mindepth 1 -print0)

php "$PACKAGE/verify.php" --installed "$PLUGIN_DIR"
php -l "$PLUGIN_DIR/core/class/ajaxSystem.class.php"
php -l "$PLUGIN_DIR/core/php/jeeAjaxSystem.php"
php -l "$PLUGIN_DIR/plugin_info/install.php"
php "$PACKAGE/validation/telemetry.php" "$PLUGIN_DIR"
```

Остання команда має завершити **217 перевірок, 0 API-запитів**. Це синтетичні тести з адаптером Jeedom у пам'яті; вони не змінюють реальну базу, не вмикають обладнання й не перевіряють доставку з хмари. Запускайте їх на **повному дереві плагіна**, а не на папці `files/`: потрібні також незмінені шаблони, зокрема Relay.

Якщо перевірки не пройшли, залиште плагін вимкненим і виправте причину або відновіть резервну копію до ввімкнення.

### 3. Увімкніть і синхронізуйте

1. Увімкніть Ajax Systems у Jeedom.
2. Запустіть штатну **Synchronisation / Synchronization** один раз і дочекайтеся завершення. Ручне копіювання не запускає update hook, тому цей крок потрібен для створення нових команд у наявних пристроях.
3. Відкрийте потрібний пристрій → **Commandes / Commands**. Перевірте наявність команд за `logicalId` з [METRICS.md](./METRICS.md). Частина діагностичних команд прихована на dashboard за замовчуванням; це не означає, що їх немає.
4. У **MQTT Manager** повторно опублікуйте discovery обладнання/команд. Перевірте `jeedom/discovery/eqLogic/#` та `jeedom/cmd/event/#`.
5. В AjaxBridge перевірте `GET /jeedom/devices` і `GET /jeedom/commands`. Для Home Assistant збережіть зв'язок із SIA через `jeedom_names`/`jeedom_command_ids`; непов'язані пристрої не публікуються за стандартного `AJAXBRIDGE_JEEDOM_DISCOVER_UNLINKED=false`.

Міграція додає лише відсутні інформаційні команди за `logicalId`; вона зберігає ID, історію, назви й налаштування вже наявних команд. Старі вимірювання не відновлюються. Не видаляйте обладнання й не перебудовуйте всі команди заради патча.

**Перезавантаження сервера зазвичай не потрібне.** Якщо PHP OPcache не перевіряє змінені файли, після успішних перевірок перезавантажте відповідну службу PHP-FPM або Apache вашої інсталяції. Не виконуйте повторні синхронізації чи reboot як спосіб отримати поля, яких немає в хмарі.

## Встановлення через SFTP / файловий менеджер

Виконайте ті самі резервне копіювання й вимкнення плагіна. Передайте **вміст `files/`**, зберігаючи регістр назв і структуру папок, у `plugins/ajaxSystem/`. Оберіть об'єднання папок та заміну однойменних файлів. Не завантажуйте їх у `plugins/ajaxSystem/files/` і не видаляйте решту плагіна. Перевірте права та, за наявності SSH/термінала, виконайте наведені перевірки. Далі увімкніть плагін, синхронізуйте й повторіть MQTT discovery.

## Перевірка результату та відомі обмеження

| Ситуація | Що перевірити |
| --- | --- |
| Button не з'явився навіть у списку Jeedom | Чи є він у відповіді списку пристроїв та чи містять деталі `deviceName` і правильний `deviceType`. Сам JSON-шаблон не створює обладнання; порожнє ім'я або відсутність пристрою у відповіді не виправляється reboot. |
| Обладнання є, але немає нових команд | Фактичний шлях копіювання, `verify.php --installed`, виконання синхронізації, точний `deviceType`, журнал `ajaxSystem`. |
| Команда є, значення порожнє/давнє | Наявність відповідного поля у snapshot/callback; модель, firmware і хмара можуть його не передавати. Нуль і `false` обробляються як значення, а не як відсутність. |
| Hub 2 Plus показує інтерфейс увімкненим, але канал неактивним | Це різні факти: `*::enabled`/`gsm::gprsEnabled` показують конфігурацію, а лише `activeChannel::*` походять із валідного списку `activeChannels`. Часткове або некоректне повідомлення зберігає останній відомий стан. |
| Потрібен один статус Jeweller online | API хаба не надає такого поля. Перевіряйте `noiseLevel::*`, параметри `jeweller::*` та `online`/`signalLevel` конкретних пристроїв; відсутність вигаданого статусу не означає збій. |
| Дані є в Jeedom, але не в AjaxBridge/HA | MQTT Manager event/discovery, теми й доступ до брокера, список команд bridge, зв'язок із SIA та параметр публікації непов'язаних пристроїв. |
| WallSwitch/Relay показує невідомий стан | Потрібен однозначний `switchState` або підтримуваний `realState`. Порожні, суперечливі прапорці та один `CONTACT_HANG` не доводять увімкнення/вимкнення. Надсилання дії On/Off саме по собі не підтверджує фізичний стан у цьому патчі. |
| LifeQualityLite має підозрілу вологість | Шаблон ділить `actualHumidity` на 10, як наявний LifeQuality. Масштабування вологості потрібно звірити з реальним payload/додатком Ajax; живої перевірки ще немає. CO₂ у Lite не додається. |

Для діагностики тимчасово ввімкніть debug-журнал `ajaxSystem`, виконайте одну синхронізацію й поверніть звичайний рівень журналювання. Лог може містити чутливі дані: перед передаванням приберіть токени, ключі, URL callback із ключами, email, ідентифікатори та приватні назви. Якщо відповідь хмари не містить Button, це питання до доступних даних/API; патч не обходить хмару й не додає окремого endpoint для кнопок.

Попередження браузера про блокування Cloudflare `beacon.min.js` політикою CSP стосується вебаналітики, а не цих метрик. Цей комплект не змінює CSP.

## Відкат

1. Вимкніть плагін у Jeedom.
2. Відновіть **усю папку** `ajaxSystem` із копії до патча. Просте накладання старих файлів залишить нові JSON-шаблони, тому нижче поточна папка спочатку зберігається під іншим ім'ям **поза каталогом плагінів**.

Укажіть саме каталог із копією, записаний під час встановлення:

```bash
set -euo pipefail
PLUGIN_DIR=/var/www/html/plugins/ajaxSystem
BACKUP_DIR=/var/backups/ajaxbridge-jeedom/REPLACE_WITH_SAVED_TIMESTAMP
test -f "$PLUGIN_DIR/plugin_info/info.json"
sudo test -f "$BACKUP_DIR/ajaxSystem/plugin_info/info.json"

FAILED_DIR="${BACKUP_DIR}-before-rollback-$(date +%Y%m%d-%H%M%S)"
sudo install -d -m 700 "$FAILED_DIR"
sudo mv "$PLUGIN_DIR" "$FAILED_DIR/ajaxSystem"
sudo cp -a "$BACKUP_DIR/ajaxSystem" "$PLUGIN_DIR"
```

3. Відкат файлів не видаляє нові команди з бази Jeedom. Для точного повернення бази/історії використайте повну резервну копію Jeedom, зроблену перед патчем; вона також поверне інші зміни Jeedom до часу копії. Якщо потрібен лише відкат коду, зайві інформаційні команди можна залишити до окремого узгодженого очищення.
4. Увімкніть плагін, перевірте його роботу та повторіть MQTT discovery, якщо змінився набір команд. За потреби врахуйте OPcache, як описано вище.

## Подальші оновлення

Оновлення плагіна з Jeedom Market може перезаписати цей патч. Після оновлення перевірте файли та потрібні команди. Не накладайте цей старий комплект автоматично поверх нового коду: спочатку порівняйте версії, перенесіть лише відсутні зміни й повторіть перевірки. Резервні копії, payload/log та власні облікові дані не додавайте до Git.

Для перевірки фактичних одиниць, формул і кешованих значень старих електричних команд використовуйте [інструмент аудиту](./tools/README.md). Він нічого не зберігає й не виконує команди пристроїв. Вивід містить локальні ID обладнання й команд; перевірте його перед публікацією.

Документація інтеграції: [Jeedom → AjaxBridge](https://github.com/RCooLeR/AjaxBridge/blob/master/bridge/docs/jeedom.md). Зміни цього комплекту: [CHANGELOG.md](./CHANGELOG.md).
